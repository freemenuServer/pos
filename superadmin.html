Access & safety

Super Admin authorization is checked against the existing public.profiles.role row. This is an application-level gate only; database policies must independently authorize administrative reads/writes.

  • Never expose Supabase service-role keys in browser code.
  • Do not create an admin account or elevate a role from this page.
  • Do not enable/disable, delete or edit a restaurant until actual columns and approved admin RLS/RPC policies are documented.
  • All admin actions should be audited with actor, target, action, timestamp and outcome.
This console can persist plan, enabled/suspended status, tax rate, feature flags and internal admin notes in restaurant_control_settings. It does not automatically suspend Supabase Auth accounts or rewrite the original menu; those require separately defined server-enforced actions.
